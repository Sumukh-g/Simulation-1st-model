# Runtime dependencies for the container image.
#
# One image serves every Python service, differing only by the command it runs.
# That is deliberate: the services currently share code across package
# boundaries (the orchestrator imports the API's models and the sim fabric, the
# sim fabric imports the domain packs), so splitting them into separate images
# today would mean untangling that coupling first. Because the entrypoints are
# already distinct per service, splitting later is a packaging change, not a
# redesign.
#
# Versions track the per-service pyproject.toml constraints. Kept off this list:
# sentence-transformers, which pulls in torch and is only needed by the evidence
# service's embedding path (see docker/Dockerfile.evidence).
